# Case Study 04｜GA4 + GSC + GTM 跨源數據儀表板

> **一句話**：把散在 GA4、Search Console、GTM 三個平台、沒人整合的數據，透過自建 MCP Server 串成一個 AI 自動生成的雙語互動儀表板，並推動 SEO 成效：核心關鍵字排名 15→7、自然曝光 +30%、Google Ads 預算 −30%。

**角色**：需求定義、追蹤架構設計、實作（獨立作業，現職）
**期間**：`【待填：起訖月份】`
**定位**：⭐ Hero 案例——MarTech PM 最直球的一個，且有[公開 Demo](https://jason0308p.github.io/GA-Dashboard/dashboard_test.html)（資料已脫敏/合成）

---

## 1. 問題

公司的數位數據散在三個互不相通的地方：**GA4**（行為數據）、**Search Console**（搜尋成效）、**GTM**（追蹤設定）。沒有人把它們放在一起看，於是行銷決策多半靠感覺，而不是靠數據。

更根本的問題：連「該追蹤什麼」都沒定義清楚——沒有一套明確的使用者行為事件，資料本身就殘缺。

## 2. 我的判斷

MarTech 的核心不是「工具會不會用」，是**讓數據能被看懂、能驅動決策**。所以我把目標定成兩層：

1. **先把追蹤補齊**——定義並埋設關鍵的使用者行為事件（20+ 個），讓資料先完整。
2. **再把跨源數據整合成一個看得懂的畫面**——不是給我自己看，是給不看 GA4 後台的人也能看懂。

## 3. 做法

**自建 GTM MCP Server**：把 GTM 的能力封裝成 AI 可呼叫的工具，讓 AI 能直接讀取、操作追蹤設定。

**AI 自動生成儀表板**：串接 GA4 Data API + GSC API + GTM，由 AI 自動產出**中英雙語**的互動式 dashboard——KPI 卡、趨勢圖、轉換漏斗、裝置分布等。

**為什麼自建 MCP 而不是手動拉報表**：手動整合三個平台的報表是一次性的、每次都要重做；封裝成 MCP 工具後，這個整合能力可以被 AI 重複呼叫、自動更新，從「一次性報表」變成「可持續的資料管線」。

## 4. 成果

| 指標 | 數字 |
|---|---|
| 核心關鍵字 GSC 排名 | 15 → 7 |
| 自然曝光 | +30% |
| Google Ads 預算 | −30%（同樣觸及下優化投放效率） |
| 埋設使用者行為事件 | 20+ 個 |
| 公開 Demo | [dashboard_test.html](https://jason0308p.github.io/GA-Dashboard/dashboard_test.html) |

> 這組 SEO/廣告數字是**全站追蹤的整體成果**，是本案例的核心產出。其他案例（如 J1 商品文案）不重複掛這組數字，避免同一份成果被算兩次。
