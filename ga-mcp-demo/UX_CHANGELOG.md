# GA + MCP Demo — UX 變更紀錄

本檔記錄展示頁的 UX 決策、驗證方式與回退線索。每次修改前先保留 Git commit；若需回退，使用 `git revert <commit>`，避免覆蓋其他作品集頁面的變更。

## 2026-11-09 — 標籤精簡、資料流程校正、時長分佈重做、GTM 後台擬真

### 目標

- 首屏不要被一堆技術標籤與流程方塊佔滿，讓訪客更快看到實際數據。
- 資料流程要符合真實因果：GTM 先決定收什麼，GA4 才收得到事件。
- 「工作階段時長分佈」必須能看出分佈形狀，且五個頁面類型要能互相比較。
- 「GTM 版本控制與變更管理」要貼近真實 Tag Manager 後台的操作感。

### 變更

**1. 技術標籤 11 → 5**

保留官方 GA MCP、GA4 Data API、GSC / GTM API、AI 跨來源分析、OAuth / Service Account；移除與其他標籤重複或過於泛用的項目（資料視覺化、純 SVG、Python 等）。首屏標籤由兩排縮為一排。

**2. 資料流程順序與節點數**

- 原本 GA4 / GSC / GTM 三者並列為步驟 1，等於把 GTM 當成與 GA4 平行的數據源，因果關係錯誤。
- 改為：`1 GTM 埋點 → 2 GA4 收集 ＋ 2 GSC 搜尋成效 → 3 官方 GA MCP → 4 AI 分析 → 儀表板`。GSC 是 Google 端的搜尋數據，與 GA4 平行取得，故同為步驟 2。
- 主節點 6 → 5（AI 分析與儀表板合併）；移除下方 3 個輔助節點（API 配額、跨資料模型對齊、GA4 抽樣），因為這三點在頁尾「技術與設計說明」已有完整說明，屬重複。流程區方塊總數 9 → 5。
- 對應 `script.js` 的 `STEPS` 改為 `[["gtm"],["ga","gsc"],["mcp"],["ai"]]`，`SIDE_AT` 清空。

**3. 工作階段時長分佈（原顯示有誤）**

原本的問題：

- 每個類型樣本數僅 220 筆，分箱後鋸齒嚴重、看不出分佈。
- 全站圖 X 軸 0–1800 秒為線性，但資料是對數常態，約八成寬度是空白。
- 五張小圖各自使用不同的 X 上限（900/1500/1200/1000/1800 秒）與不同分箱寬度，且各自對自己的最大值正規化，**彼此根本無法比較**，但這一區的用途正是比較頁面類型。
- 完全沒有 Y 軸刻度。

改為：

- 樣本數 220 → 2400／類型。
- 五張圖共用 `0–600 秒`、`20 秒` 分箱；超過 600 秒的長尾收斂在最後一個分箱並標示 `600s+`。
- Y 軸改為「該類型工作階段佔比（%）」，附格線與刻度，不同樣本數也能並排比較。
- 加入中位數虛線；僅全站圖顯示中位數文字，小倍數圖只畫線以免與刻度重疊。
- Tooltip 同時顯示筆數與百分比。

**4. GTM 版本控制與變更管理**

改寫成仿 Tag Manager 後台的介面：

- 頂部工具列：Tag Manager 標題、帳戶 / 容器麵包屑、「預覽」「提交變更」按鈕（停用，並標註權杖未授予 publish）。
- 「變更摘要 / 版本」兩個分頁。
- 工作區 vs 線上已發布版本的並排比較，附狀態圓點與「3 項工作區變更」計數。
- 變更清單改為表格：類型（變數／標籤）、名稱、變更徽章（新增／已修改）、說明。
- 新增「版本」分頁：版本號、名稱、發布時間、發布者，線上版本加 `線上` 標記，並說明可 rollback。
