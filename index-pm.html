Schooling｜互動式 SQL 課程平台

讓想學 SQL 的人在瀏覽器裡直接練，不用裝資料庫、不用註冊、不用後端
產品決策的核心是把註冊與環境安裝這兩道放棄點直接拿掉：打開網頁就能寫 SQL。 因此架構上刻意不做後端（WASM SQLite 跑在瀏覽器裡）——換來零維運成本與使用者資料不離開瀏覽器的隱私優勢，代價是放棄跨裝置同步與學習數據收集，這是明知取捨後的選擇。 驗收標準上，自動批改比對查詢結果而非 SQL 字串：同一題允許多種正確寫法，避免把「寫法不同」誤判成「答錯」而打擊學習者。

GA4 / GSC 行銷分析儀表板

讓主管看得懂詢價從哪來，讓行銷與工程能安全改追蹤設定

03. 關於我

我做產品的方式是先問「誰被卡住、卡住的成本是多少」，再決定要不要做、做到什麼程度。 因為自己寫得出來，所以在 build-vs-buy 的討論裡我能給出有根據的估算，而不是只能等工程回報；也因為自己維運過，所以會把維護成本算進決策。

導入 AI 與自動化時，我的立場是先定義錯誤的代價，再決定自動化的程度：報價錯一次的損失、法規下架漏一件的風險、追蹤設定被誤改的後果——這些決定了哪裡該全自動、哪裡該留人工關卡。

學術背景是數學系（高雄大學）與經濟研究所（台北大學）。研究所期間擔任助教，負責出考題；大學時參與教育部偏鄉計畫擔任帶班老師。 出考題其實就是定義「什麼叫做學會了」——跟定義驗收標準是同一種能力：你得先講清楚什麼算及格，別人才有辦法做到。偏鄉帶班則讓我習慣對著完全不同背景的人把事情講懂，這在跨部門推動採用時每天都在用。
