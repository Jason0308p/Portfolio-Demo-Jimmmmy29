# LINE RAG Demo — UX 變更紀錄

本檔記錄展示頁的 UX 決策、驗證方式與回退線索。每次修改前先保留 Git commit；若需回退，使用 `git revert <commit>`，避免覆蓋其他作品集頁面的變更。

## 2026-11-09 — 互動區與說明區分層

### 目標

- 訪客打開頁面最先看到的，應該是**實際的 AI 客服回覆結果**，而不是架構圖。
- 「處理流程」「冷熱判斷閘道」「接點說明」本質是說明性內容，不應與對話框爭奪同等視覺權重。

### 變更

- 版面拆成兩段：上方「互動體驗：實際對話結果」只放對話框與範例問題；下方新增「背後怎麼運作（說明）」區塊。
- 對話框由跨 2 欄改為跨 3 欄（1440px 下 522px → 789px），高度 440px → 520px，成為頁面主角。
- 「試試這些問題」改為與對話框同排同高的 1 欄（互動入口，仍屬互動區）。
- 「處理流程」移入說明區並改為橫排管線，卡片高度 442px → 123px；時間軸改為可捲動。
- 說明區三張卡改用低彩度底色與虛線分隔線，明確低於互動區的視覺層級。
- 說明區仍會隨提問同步亮燈，只是不再搶走第一眼。

### 驗證清單

- 1440px：送出「GIFT-1001 的最小訂購量？」，確認回覆訊息、6 個流程節點、冷熱閘道命中 1 列、時間軸 7 列與狀態列「319ms 完成」皆正常。
- 390px：無水平溢位，堆疊順序為 對話 → 範例問題 → 說明區。
- 未更動任何 JS 依賴的 id 與 class（`#msgs`/`#chips`/`#cpipe`/`#timeline`/`#cgateTree`/`#traceSummary`、`.node[data-k]`、`.gate-row[data-row]`）。

### 回退

- 本輪 UI/UX 調整前的還原點：tag `uiux-before-20261109`（commit `9e7a605`）。
- 只回退本頁：`git log --oneline -- line-rag-demo` 找出本次 commit，再 `git revert <commit>`。

## 2026-07-27 — 互動展示可讀性優化

### 目標

- 桌機先看懂 LINE 對話，再理解背後 RAG 流程。
- 手機不必在聊天、完整流程與範例題目之間失去閱讀脈絡。
- 將技術實作轉成一次提問後可立即理解的結果摘要。

### 變更

- 桌機採聊天主欄與精簡 AI 處理欄；下方才呈現完整範例題目。
- 右欄新增本次結論：路由類型、資料來源與總耗時。
- 問題命中後，冷熱閘道只顯示實際命中的分支；完整規則仍保留在技術說明。
- 歡迎訊息新增三個 quick replies，降低手機首屏的空白感並提供明確起點。
- 手機只顯示前三個技術標籤，其他收斂為技術數量提示。
- 輸入框文案改為「點下方範例」，與現行版面一致。
- 聊天與處理紀錄使用細緻深色捲軸，降低視覺干擾。
- 移除重複的手機流程抽屜節點，避免同 ID 造成互動行為不穩定。

### 驗證清單

- 桌機：1440px 寬，送出商品、FAQ、模糊需求與混合問題各一題。
- 手機：390px 寬，確認標籤不橫向溢位、quick replies 可點、流程抽屜可開關。
- 功能：每題都應有訊息回覆、節點動畫、命中閘道與時間紀錄。
- 品質：執行 `node --check line-rag-demo/script.js` 與 `git diff --check`。

- 本次實作：`Improve LINE RAG demo onboarding`；以 `git log --oneline -- line-rag-demo` 找出對應 commit，再使用 `git revert <commit>` 回退。
