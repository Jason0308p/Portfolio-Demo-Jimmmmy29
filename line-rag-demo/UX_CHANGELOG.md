# LINE RAG Demo — UX 變更紀錄

本檔記錄展示頁的 UX 決策、驗證方式與回退線索。每次修改前先保留 Git commit；若需回退，使用 `git revert <commit>`，避免覆蓋其他作品集頁面的變更。

## 2026-07-27 — 互動展示可讀性優化

### 目標

- 桌機先看懂 LINE 對話，再理解背後 RAG 流程。
- 手機不必在聊天、完整流程與範例題目之間失去閱讀脈絡。
- 將技術實作轉成一次提問後可立即理解的結果摘要。

### 變更

- 桌機採聊天主欄與精簡 AI 處理欄；下方才呈現完整範例題目。
- 右欄新增本次結論：路由類型、資料來源與總耗時。
- 問題命中後，冷熱閘道只顯示實際命中的分支；完整規則仍保留在技術說明。
- 歡迎訊息新增三個 quick replies，降低手機首屏的空白感並提供明確起點。
- 手機只顯示前三個技術標籤，其他收斂為技術數量提示。
- 輸入框文案改為「點下方範例」，與現行版面一致。
- 聊天與處理紀錄使用細緻深色捲軸，降低視覺干擾。
- 移除重複的手機流程抽屜節點，避免同 ID 造成互動行為不穩定。

### 驗證清單

- 桌機：1440px 寬，送出商品、FAQ、模糊需求與混合問題各一題。
- 手機：390px 寬，確認標籤不橫向溢位、quick replies 可點、流程抽屜可開關。
- 功能：每題都應有訊息回覆、節點動畫、命中閘道與時間紀錄。
- 品質：執行 `node --check line-rag-demo/script.js` 與 `git diff --check`。
